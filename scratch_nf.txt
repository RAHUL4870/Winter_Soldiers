<h2 id="what">1. What This Product Is</h2>

<p>NexaFreight Control Tower ingests 180,000 DataCo orders, consolidates them into realistic multi-modal shipments, assigns real vessels tracked via AISStream WebSocket, simulated flights on real geodesic arcs, and interpolated trucks on real road geometries. It monitors every shipment in real-time, detects disruptions automatically from port congestion data, AIS deviation, or manual entry, evaluates the financial impact across every order inside the affected shipment, generates 3 rerouting options with full cost/SLA/CO2 analysis, presents them to an operator for approval, logs every decision immutably, and feeds those decisions back as training data.</p>

<div class="callout info">
  <strong>Industry Category</strong>
  This is a <strong>Logistics Control Tower (LCT)</strong>. Companies like Flexport, project44, FourKites, SAP TM, and Kinaxis sell enterprise versions for millions of dollars. NexaFreight is a portfolio-grade open-source implementation of the same category.
</div>

<h3>The Core Workflow</h3>
<pre>
ORDER placed by customer
  ↓
Multiple ORDERS consolidated into one SHIPMENT (physical container)
  ↓
SHIPMENT assigned a multi-leg ROUTE (first mile → sea/air → last mile)
  ↓
Real ASSETS assigned (vessel MMSI, flight arc, truck road polyline)
  ↓
Live EVENTS update shipment progress (AIS, simulation, manual)
  ↓
DISRUPTION detected (port congestion, vessel delay, strike)
  ↓
ALERT fired: ETA impact + per-order SLA check + financial exposure
  ↓
REROUTING ENGINE generates 3 options (accept / divert / modal shift)
  ↓
FINANCIAL ENGINE scores each option (cost + SLA penalties + CO2)
  ↓
OPERATOR approves one option
  ↓
SYSTEM executes: updates legs, increments route_version, writes audit log
  ↓
Decision becomes training data for next ML cycle
</pre>

<h3>The Key Rule</h3>
<div class="callout warn">
  <strong>Always Remember</strong>
  Physical movement = per <strong>SHIPMENT</strong> (one container).<br/>
  Financial impact = per <strong>ORDER</strong> (each has its own SLA and penalty).<br/>
  Rerouting decision = weighs <strong>ALL orders</strong> inside the shipment together.
</div>

<h2 id="concepts">6. Core Concepts</h2>

<h3>The Data Hierarchy</h3>
<pre>
CUSTOMER
  └── ORDER (one DataCo row = one order)
        └── ORDER_ITEMS (products within the order)
              └── SHIPMENT (multiple orders consolidated together)
                    └── LEGS (sequential route segments)
                          └── EVENTS (things that happen on each leg)
</pre>

<h3>Provenance Labels</h3>
<p>Every value in the system must carry one of these labels. No exceptions.</p>

<p>
  <span class="badge real">REAL</span> Live feed, confirmed by external source. Example: AIS position from AISStream.<br/>
  <span class="badge rep">REPLAYED</span> Historical data served as if live. Example: AIS from NOAA Parquet file.<br/>
  <span class="badge derived">DERIVED</span> Computed from real data. Example: ML prediction, consolidated shipment.<br/>
  <span class="badge cal">CALIBRATED</span> From authoritative reference data. Example: UN/LOCODE coordinates.<br/>
  <span class="badge sim">SIMULATED</span> Interpolated or generated. Example: truck position on road polyline.
</p>

<h3>Status Lifecycles</h3>
<pre>
Shipment:  PLANNED → IN_TRANSIT → AT_PORT → IN_TRANSIT → DELIVERED
Alert:     OPEN → ACKNOWLEDGED → OPTIONS_GENERATED → DECISION_PENDING → APPROVED → EXECUTED
Leg:       PLANNED → IN_PROGRESS → COMPLETED
                                → REPLACED  (if rerouted — never deleted)
</pre>

<h2 id="adapter">7. Adapter Pattern</h2>
<p>Every external dependency implements a Protocol. Swap the adapter, not the business logic. Tests use MockAdapter. Development uses AISStream + ReplayFlight + TruckSim. Production adds no new code.</p>
<pre>
# adapters/protocols.py

from typing import Protocol
from dataclasses import dataclass
from datetime import datetime
from enum import StrEnum

class AssetType(StrEnum):
    VESSEL   = "VESSEL"
    AIRCRAFT = "AIRCRAFT"
    TRUCK    = "TRUCK"

class Provenance(StrEnum):
    REAL      = "REAL"
    REPLAYED  = "REPLAYED"
    SIMULATED = "SIMULATED"
    MOCK      = "MOCK"

@dataclass(frozen=True)
class PositionReport:
    asset_type:   AssetType
    asset_id:     str
    lat:          float
    lon:          float
    speed_knots:  float | None
    heading_deg:  float | None
    reported_at:  datetime
    provenance:   Provenance
    source:       str

@dataclass(frozen=True)
class FeedHealth:
    adapter_name:      str
    is_healthy:        bool
    last_success:      datetime | None
    messages_received: int
    provenance:        Provenance

class FeedAdapter(Protocol):
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
    async def get_latest_position(self, asset_id: str) -> PositionReport | None: ...
    async def health(self) -> FeedHealth: ...
</pre>

<h2 id="ais">8. Ship Tracking — AISStream.io</h2>

<div class="callout success">
  <strong>Why AISStream</strong>
  Free WebSocket API. No rate limits in the REST sense. Persistent stream — subscribe once, it pushes continuously. Filter by specific MMSIs. No paid tiers. API key is free on registration (GitHub OAuth).
</div>

<h3>Critical Caveats</h3>
<ul>
  <li>No direct browser connections. Always proxy through your server.</li>
  <li>Connection drops every ~2 minutes sometimes. Build reconnect with exponential backoff.</li>
  <li>Consume messages fast enough or the service drops them.</li>
  <li>From September 2026: uncompressed connections subject to bandwidth limits. Enable <code>permessage-deflate</code> compression.</li>
  <li>No SLA or uptime guarantee. Plan for interruptions. Fallback to REPLAYED.</li>
</ul>

<h3>Connection Architecture</h3>
<pre>
AISStream.io WSS endpoint
        ↓
AISStreamAdapter (background asyncio task)
  - Connect on startup
  - Subscribe: FiltersShipMMSI (your 20-50 active vessel MMSIs)
               FilterMessageTypes: ["PositionReport"]
  - On each message: parse → update in-memory cache → write to DB
  - On disconnect: exponential backoff (1s, 2s, 4s… max 60s)
  - Resubscribe within 3 seconds of reconnect
  - Track health: last_success, messages_received, is_healthy
        ↓
In-memory cache (dict[MMSI → PositionReport])
        ↓
SSE endpoint pushes all positions to frontend every 5 seconds
</pre>

<h3>MMSI Assignment Strategy</h3>
<p>Do NOT subscribe to all ships globally. For each unique (origin_port, dest_port) sea lane in your DataCo data: research 2-3 real vessels that operate that trade lane (Maersk/COSCO/Evergreen), look up their MMSI on MarineTraffic vessel finder (free search, no API needed), insert into vessels table. Subscribe to exactly these 20-50 MMSIs via <code>FiltersShipMMSI</code>.</p>

<h2 id="flights">9. Flight Tracking — Simulated</h2>

<div class="callout warn">
  <strong>Why Not OpenSky Live</strong>
  Auth changed to OAuth2 in March 2026. Raw ADS-B gives lat/lon/callsign but no flight number, airline, or origin/destination. Non-commercial license only. Coverage gaps outside EU/NA.
</div>

<h3>What Simulated Means — Not Fake</h3>
<p>The geometry IS real. Flights fly great-circle arcs. The duration IS real from actual flight schedule data. The speed IS realistic (~900 km/h cruise). You label it <span class="badge sim">SIMULATED</span>. The operator knows it is not live ADS-B. The route drawn on the map is geometrically correct.</p>

<h3>How It Works</h3>
<pre>
1. For each DataCo AIR lane (e.g. PVG → LAX):
   - Compute geodesic arc between airport coords (geopy)
   - Store as GeoJSON LineString in legs.route_geometry
   - Get realistic flight duration from OpenFlights data
   - Assign a real cargo flight number (Cathay Cargo, FedEx, DHL)

2. When leg status = IN_PROGRESS:
   progress  = elapsed_time / planned_duration_hours   (0.0 → 1.0)
   position  = interpolate_along_arc(origin, dest, progress)
   speed     ≈ 485 knots cruise
   heading   = bearing from current to next point

3. position_interpolator worker runs every 30 seconds
   → writes PositionReport(provenance=SIMULATED, source=GEODESIC_ARC)
</pre>

<h2 id="trucks">10. Truck Tracking — Road Interpolation</h2>

<h3>Problem 1: Route Geometry</h3>
<p>Use <strong>OpenRouteService free tier</strong> (40 req/min, 2000 req/day). Profile: <code>driving-hgv</code>. You have ~200 unique city pairs in DataCo. Pre-compute ALL 200 at build time. Cache GeoJSON in the DB. Uses ~200 of 2000 daily free requests. Done in one afternoon. Never call again.</p>

<h3>Problem 2: Current Position</h3>
<p>Interpolate along the cached road polyline using Shapely. This is identical to how Google Maps shows your GPS dot between actual pings.</p>
<pre>
from shapely.geometry import LineString
import json

def get_truck_position(leg, current_time):
    elapsed  = (current_time - leg.actual_departure).total_seconds()
    progress = min(elapsed / leg.planned_duration_seconds, 1.0)

    line  = LineString(json.loads(leg.route_geometry)["coordinates"])
    point = line.interpolate(progress, normalized=True)

    return PositionReport(
        asset_type  = AssetType.TRUCK,
        asset_id    = str(leg.id),
        lat         = point.y,
        lon         = point.x,
        speed_knots = 60.0 / 1.852,     # ~60 km/h average truck
        heading_deg = compute_heading(line, progress),
        reported_at = current_time,
        provenance  = Provenance.SIMULATED,
        source      = "ROAD_INTERPOLATION"
    )
</pre>

<h2 id="searoute">11. Sea Routes — searoute-py</h2>

<div class="callout danger">
  <strong>Critical Rule</strong>
  Pin version hard: <code>searoute==1.4.3</code>. Pre-compute at build time only. Store GeoJSON in DB. Never call at request time. The library is unmaintained — it must never be a runtime dependency.
</div>

<h3>What It Does</h3>
<p>Contains a pre-built maritime network graph (Marnet). Includes passages through Suez Canal, Panama Canal, Malacca Strait, Gibraltar, Dover Strait. Runs Dijkstra on the graph and returns a GeoJSON LineString that follows actual ocean routes, avoiding land.</p>

<h3>Build-Time Pattern</h3>
<pre>
import searoute as sr, json

try:
    route = sr.searoute(
        [origin_port.lon, origin_port.lat],   # [lon, lat] — NOTE the order
        [dest_port.lon,   dest_port.lat],
        units="naut"
    )
    geometry      = json.dumps(route["geometry"])
    distance_nm   = route["properties"]["length"]
    route_quality = "COMPUTED"

except Exception:
    # Fallback: great-circle line
    geometry      = make_great_circle_geojson(origin_port, dest_port)
    distance_nm   = haversine_nm(origin_port, dest_port)
    route_quality = "APPROXIMATE"

# Store in DB. Done. Never call searoute again at runtime.
</pre>

<div class="callout warn">
  <strong>Coordinate Convention</strong>
  searoute-py uses [longitude, latitude] (GeoJSON order). geopy uses (latitude, longitude). Never confuse these — they produce wrong routes silently.

<h2 id="consolidation">12. Shipment Consolidation</h2>

<h3>Why Consolidation Is Necessary</h3>
<p>DataCo has 180,000 individual order rows. In reality you do not send one container per order. Multiple orders going the same direction by the same mode are consolidated into one physical shipment.</p>

<h3>Consolidation Rules</h3>
<p>Group orders into the same shipment when ALL of these match:</p>
<ol>
  <li>Same origin region (country code prefix of UN/LOCODE)</li>
  <li>Same destination region</li>
  <li>Compatible shipping mode (all SEA, or all AIR, etc.)</li>
  <li>Compatible cargo class (no HAZMAT with GENERAL)</li>
  <li>Departure windows overlap (orders placed within same 3-day window)</li>
  <li>Combined weight/volume fits in one container</li>
</ol>

<h3>Expected Output</h3>
<p>From 180,000 DataCo orders: approximately <strong>5,000–10,000 shipments</strong>. Each contains 10–40 orders. Of those, roughly <strong>47 are ACTIVE</strong> (IN_TRANSIT) at any given moment. This is realistic for a mid-size freight forwarder operations desk.</p>

<div class="callout info">
  <strong>The Critical Implication</strong>
  The STRICTEST SLA deadline among all orders in the shipment drives the shipment's urgency. If one order has a 20-day SLA and 19 others have 30-day SLA, the shipment must move as if it has a 20-day SLA.
</div>

<h2 id="alert">14. Alert Engine</h2>

<h3>What The Alert Engine Computes</h3>
<p>For each disruption → affected shipment pair:</p>
<ol>
  <li>Revised ETA = current ETA + disruption.estimated_delay_hours</li>
  <li>For each order: is <code>revised_eta &gt; order.sla_deadline</code>?</li>
  <li>Days late per order = <code>max(0, (revised_eta - sla_deadline).days)</code></li>
  <li>SLA penalty per order = <code>revenue × sla_penalty_pct × days_late</code></li>
  <li>Total SLA penalties = sum across all orders</li>
  <li>Demurrage = <code>max(0, port_dwell_days - free_days) × daily_rate</code></li>
  <li>Financial exposure = SLA penalties + demurrage</li>
</ol>

<h3>Severity Thresholds</h3>

<h2 id="reroute">15. Rerouting Engine</h2>

<div class="callout info">
  <strong>What Rerouting Actually Means</strong>
  Rerouting does NOT redirect a ship mid-ocean. It changes the REMAINING legs of the journey after the current leg completes. The vessel finishes what it is doing. You change what happens next.
</div>

<h3>The Three Option Types</h3>
<h4>Option A: Accept Delay</h4>
<p>Always included as baseline. Keep original route. Accept the delay and penalties. Use when all SLAs still met, or rerouting costs more than demurrage + penalties.</p>

<h4>Option B: Divert to Alternative Node</h4>
<p>Change the destination port/airport to avoid the disrupted one. Same primary mode. Different transshipment point. Use when nearby port is clear and last-mile cost is acceptable.</p>

<h4>Option C: Modal Shift or Split</h4>
<p>Switch from sea to air for remaining journey. OR split the shipment: priority orders go air, rest stay on sea. Use when SLA breach is imminent and the penalty exceeds the air premium.</p>

<h3>Corridor Alternatives (Stored in DB, Not Computed Live)</h3>
<pre>
Example for Shanghai → Long Beach:

ALT1: Via Oakland
  when_to_use: [PORT_CONGESTION, PORT_STRIKE]
  time_delta_hours: -48   (2 days faster via less congested port)
  cost_delta_factor: 1.08 (8% more expensive)

ALT2: Via Seattle + Rail
  when_to_use: [PORT_CONGESTION, WEATHER, CANAL_CLOSURE]
  time_delta_hours: -72
  cost_delta_factor: 1.05

ALT3: Air Freight (priority cargo only)
  when_to_use: [SLA_CRITICAL, HIGH_VALUE_CARGO]
  time_delta_hours: -300  (much faster)
  cost_delta_factor: 5.5  (air is 5-6x sea cost per kg)
</pre>

<h3>Scoring Function</h3>
<pre>
For each option:
  revised_eta            = compute from new legs
  sla_breaches           = check all orders vs revised_eta
  sla_penalties          = sum per-order penalties (see Financial Engine)
  demurrage              = (dwell_days - free_days) × daily_rate
  freight_delta          = new_freight_cost - original_planned_cost
  reroute_cost           = rebooking + transshipment fees
  co2_delta              = new_co2 - original_planned_co2
  carbon_cost            = co2_delta × carbon_price_per_kg
  total_financial_impact = sum of all above

Rank: lowest total_financial_impact = best option
Mark: AI recommendation = best-ranked option that also meets SLA
Show: top 3 options only (always include Accept Delay)
</pre>

<h3>The Split Decision</h3>
<pre>
Evaluate split when: some orders breach SLA and others do not.

priority_orders  = [o for o if revised_eta > o.sla_deadline]
standard_orders  = [o for o if revised_eta &lt;= o.sla_deadline]

total_sla_penalties = sum(calculate_penalty(o) for o in priority_orders)
air_cost            = sum(estimate_air_freight(o) for o in priority_orders)

if total_sla_penalties > air_cost:
    RECOMMEND SPLIT:
      priority_orders → air freight → meets all SLAs
      standard_orders → stay on sea → all SLAs met anyway
      net_savings = total_sla_penalties - air_cost
</pre>

<!-- ═══ SECTION 16 ═══ -->
<h2 id="finance">16. Financial Engine</h2>

<h3>Complete Cost Breakdown Per Option</h3>
<pre>
Revenue              = agreed freight rate (from DataCo Sales column)
Freight cost         = carrier rate × distance × weight
Port handling        = origin terminal + destination terminal fees
Demurrage            = max(0, dwell_days - free_days) × daily_rate
SLA penalties        = per-order: revenue × penalty_pct × days_late
Rerouting surcharge  = rebooking fee + transshipment cost
Carbon cost          = co2_kg × carbon_price_per_kg  (default $0.08/kg)

Gross margin         = Revenue - sum(all costs)
Decision             = option with lowest total_financial_impact
                       that satisfies SLA constraints
</pre>

<div class="callout info">
  <strong>Carbon Price Default</strong>
  $0.08 per kg CO2 = ~$80 per tonne. This approximates the EU ETS shadow price. Configurable via environment variable.
</div>

<h3>Model 2: ETA Quantile Regressor (LightGBM)</h3>
<p>Three separate models: <strong>P10</strong> (optimistic), <strong>P50</strong> (median), <strong>P85</strong> (conservative). Target = <code>actual_transit_days - planned_transit_days</code> (the residual, not absolute). Evaluated on pinball loss. P10-P85 interval must contain actual result ~75% of the time. <strong>Use P85 for SLA risk checks</strong> — protects operator from surprises.</p>

<h3>Model 3: Demand Forecast (StatsForecast AutoETS)</h3>
<p>Weekly order volume per (product_category × origin_region × dest_region). 30/60/90-day horizon. Point forecast + confidence intervals. Used for capacity pre-negotiation, not individual shipment decisions. StatsForecast is 100x faster than Prophet with no PyStan dependency.</p>

// frontend/src/api/sse.ts
export function useSSEPositions(): Position[] {
  const [positions, setPositions] = useState&lt;Position[]&gt;([]);

  useEffect(() =&gt; {
    const es = new EventSource('/api/map/positions/stream');

    es.onmessage = (e) =&gt; {
      const data = JSON.parse(e.data);
      if (data.type === 'POSITION_UPDATE') setPositions(data.positions);
    };

    // EventSource auto-reconnects. No manual logic needed.
    return () =&gt; es.close();
  }, []);

  return positions;
}

<h2 id="pipeline">22. Data Pipeline Scripts</h2>
<p>Run in order. Once. Never again unless source data changes.</p>

<pre>
Script 01: ingest_dataco.py
  Input:  DataCoSupplyChainDataset.csv
  Output: orders + order_items tables
  - Map shipping_mode → SEA|AIR|RAIL
  - Compute sla_deadline = order_date + sla_days
  - Map product_category → cargo_class
  - Derive sla_penalty_pct by customer_segment
  - provenance = DERIVED, source = DATACO_CSV

Script 02: ingest_unlocode.py
  Input:  unlocode.csv
  Output: locations table
  - Parse UN/LOCODE 5-char codes
  - Convert lat/lon from DDMM format to decimal degrees
  - provenance = CALIBRATED, source = UNECE_UNLOCODE

Script 03: ingest_port_data.py
  Input:  port_activity.csv + maritime_port_performance.csv
  Output: ports + port_daily_stats tables
  - Fuzzy match port names to UN/LOCODE
  - Compute baseline avg_turnaround_hours (90-day average)
  - Compute daily congestion_index per port

Script 04: consolidate_shipments.py
  Input:  orders table
  Output: shipments table, orders.shipment_id updated
  - Group by (origin_country, dest_country, mode, cargo_class, week)
  - Fill containers (max 20 orders or weight limit)
  - strictest_sla_deadline = min(order.sla_deadline) per group

Script 05: plan_routes.py
  Input:  shipments + locations + ports tables
  Output: legs table with route_geometry (GeoJSON cached)
  - SEA legs: searoute-py → GeoJSON + distance_nm
             Failure → great-circle fallback, route_quality=APPROXIMATE
  - ROAD legs: OpenRouteService (driving-hgv profile), batch 40/min
  - AIR legs: geodesic arc (geopy), duration from OpenFlights
  - CO2 per leg (GLEC factors): SEA=6.5, AIR=500, ROAD=62, RAIL=22 g/tonne-km
  - Chain planned_departure/arrival through all legs

Script 06: assign_vessels.py
  Input:  legs (SEA, MAIN_HAUL only)
  Output: vessels table + legs.vessel_id updated
  - Research real vessels per trade lane (Maersk/COSCO/Evergreen)
  - Get MMSI from MarineTraffic free search
  - Assign MMSIs round-robin to sea legs

Script 07: assign_flights.py
  Input:  legs (AIR, MAIN_HAUL only)
  Output: legs.flight_number + planned_duration_hours updated
  - Pick real cargo flights per airport pair
  - Duration from OpenFlights database

Script 08: download_ais_history.py
  Input:  MMSIs from vessels table
  Output: data/raw/ais_historical/*.parquet
  - Download from NOAA Marine Cadastre (US waters, free)
    OR Danish Maritime Authority (global, research license, free)
  - Filter to your MMSIs only
  - Convert CSV → Parquet (10x smaller)
  - Used by ReplayFeedAdapter when USE_LIVE_AIS=false

Scripts 09–11: Train ML models
  - Run after Phase 1 data is complete
  - Time-based splits (no data leakage)
  - Optuna hyperparameter search
  - Must beat naive baseline
  - Save model.joblib + feature_schema.json + metadata.json
</pre>

    <tr><td>ML model not found at startup</td><td>FileNotFoundError in registry</td><td>Log error. Disable prediction endpoints. Serve 503 with message</td></tr>
    <tr><td>DuckDB analytics query slow</td><td>Response &gt; 3s</td><td>Add DuckDB index on hot columns</td></tr>
    <tr><td>SQLite write contention</td><td>Concurrent writes</td><td>WAL mode enabled in <code>connect_args</code></td></tr>

<h2 id="provenance">27. Provenance Rule</h2>

<div class="callout success">
  <strong>The One Rule That Governs Everything</strong>
  Every value in the system has one of five labels. If you cannot label it, you do not ship it.
</div>

<div class="table-wrap">
<table>
  <thead><tr><th>Label</th><th>Meaning</th><th>Frontend</th></tr></thead>
  <tbody>
    <tr><td><span class="badge real">REAL</span></td><td>Live feed, confirmed by external source. AIS position from AISStream</td><td>No badge (clean, trusted)</td></tr>
    <tr><td><span class="badge rep">REPLAYED</span></td><td>Historical data served as if live. AIS from NOAA Parquet file</td><td>Grey "R" badge</td></tr>
    <tr><td><span class="badge derived">DERIVED</span></td><td>Computed from real data. ML prediction, consolidated shipment</td><td>Labeled as "prediction" — no badge needed</td></tr>
    <tr><td><span class="badge cal">CALIBRATED</span></td><td>From authoritative reference. UN/LOCODE coordinates, port dwell times</td><td>No badge (reference data is trusted)</td></tr>
    <tr><td><span class="badge sim">SIMULATED</span></td><td>Interpolated or generated. Truck on road polyline, flight on arc</td><td>Yellow "S" badge</td></tr>
  </tbody>
</table>
</div>

<p>Every API response that contains a position, prediction, cost, or ETA must include a <code>provenance</code> field. This is enforced by Pydantic schema. If provenance is missing from any response: it is a bug, not a feature.</p>
